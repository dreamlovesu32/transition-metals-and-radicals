# 共用阅读模板与文章数据入口

所有文章复用同一套阅读页面、切图、批注、导航和导出组件。新稿只需填写文章配置、中文导读、原论文裁图与封面，调整切图设置；不复制或修改网页源码。`articles/` 根目录中的 `<article-id>.json` 自动登记到本地目录，新增文章不再修改 Python/JavaScript 的篇目清单或 `active-article.json`。活动指针只保留默认文章入口用途。

## 准备文件

复制 `templates/article-manifest.example.json` 为 `articles/<article-id>.json`，把 `templates/content-zh.example.md` 复制为 `articles/<article-id>/content-zh.md`。英文稿可稍后提供；模板中的英文路径仍需独立填写。原论文 PDF/SI 保持原文件与原位置不动，不上传。裁图放 `articles/<article-id>/figures/`，封面放 `covers/<article-id>.png`。

完整配置模板包含题名、DOI、完整刊名、首次正式在线日期、类别、审稿状态、封面、内容与状态路径、配图及切换参数。示例文字和日期都是填写占位，须替换为已核对信息。

- `id`：小写字母、数字或连字符，必须与 manifest 文件名相同。`readingId` 是稳定文献编号，不能与其他文章重复；`displayNumber` 是篇号元数据。
- `title.zh/en`：已核对题名。`doi`、`journal`、`published`（YYYY.MM）、`firstPublishedOn`（YYYY-MM-DD，只有月份证据时可写 YYYY-MM）须彼此一致。`sourceUrl` 使用已核对的 HTTPS 出版社页或 DOI 链接。
- `kind`：`research` 或 `review`。新稿 `reviewStatus` 填 `pending`。这个字段本身不构成公开许可。
- `sourcePdf` 从 `D:\Read` 起算；其余文件路径从 `D:\Read\导读工作台` 起算。统一使用 `/`，不得用绝对路径或跳出项目。
- `content.zh/en` 是首次导入的 Markdown；`state.zh/en` 是此后已保存正文的权威来源。每篇每种语言须使用独占 state 路径。已有 state 时改 Markdown 不会覆盖网页编辑；正文修订应走现有修订/审稿流程，保留历史版本与批注。
- `figures` 按配图首次出现顺序列出 `file` 与原 PDF 页码 `page`。每项文件名唯一，页码为正整数。每次在正文再次使用同一裁图，可重复图片行，形成独立配图块，不必复制图片文件。

## 正文与切图

正文先写一个 `# 论文题名`，再按当前写作规范组织 `##` 至 `####` 标题和段落。图片单独成行：

```markdown
![准确图注与原论文定位](figures/figure-01.png)
```

默认读到图片行时切到这张图。移动作者稿中的图片行可以调整首次导入的配图位置。导入后按块 ID 配置锚点，避免复制页面代码。图注不可空，所有使用的图片必须出现在 manifest 且文件确实存在。

可选 `reading` 为版本化切图设置；缺省时保留旧稿行为，`scrollThreshold` 仍兼容。模板默认如下：

```json
"reading": {
  "version": 1,
  "downThreshold": 0.52,
  "upBuffer": 0.18,
  "endBuffer": 0.25,
  "switches": []
}
```

`downThreshold` 是向下切图位置占正文视口高度的比例，范围大于0且小于1。`upBuffer` 是普通上行缓冲，`endBuffer` 是末图离底退出缓冲，范围0至1；这些是距离参数，不是延时。省略字段分别使用0.52（或旧 `scrollThreshold`）、0.18、0.25。

`switches` 是按 figure block ID 指定的稀疏覆盖，图片顺序仍来自当前权威正文，不维护第二套排序。先运行 `plan` 查真实 `figureId`、默认 `anchorId`；输出的 `anchors` 列表列出所有可用块 ID、类型与文字预览，可直接选择需要的段落或标题，不必改源码。示例：

```json
"switches": [
  {"figureId": "真实配图块ID", "trigger": "block", "anchorId": "真实段落或标题块ID"},
  {"figureId": "真实末图块ID", "trigger": "article-end"}
]
```

锚点可指任何已存在的正文块。`article-end` 仅允许最后一张配图且不填 `anchorId`，适合末尾附图，无须另造正文小节。未知锚点、重复配图覆盖或非末图触底设置均会校验失败。旧稿最后 figure block 的 `scrollTrigger: "article-end"` 自动兼容；无需改旧 state。

## 本地命令与预览

在 `D:\Read\导读工作台` 执行：

```powershell
python validate_article.py validate articles/<article-id>.json
python validate_article.py plan articles/<article-id>.json
python validate_article.py build articles/<article-id>.json
python validate_article.py build articles/<article-id>.json --preview
```

`validate` 只读检查完整题录、目录冲突、正文结构、封面/PDF/裁图文件、块 ID 与切图锚点。新稿若已存在 state 会提示保护；要检查现有稿，加 `--existing`。旧用法 `python validate_article.py articles/<article-id>.json --existing` 继续有效。

`plan` 只读输出 JSON 切图计划，优先使用已保存 state；state 不存在才解析 Markdown。`build` 先检查数据，再仅创建缺失的 state，保留所有已有 state。新建时记录真实保存时间，不把构建当成已有正文更新。它不改活动指针、审稿状态、批准版本或公开白名单。

`--preview` 额外调用现有 `D:\Read\工具\构建审稿预览.py`，生成 `D:\Read\审稿预览`；该目录含私有待审稿，禁止上传。日常本地动态入口仍为 `http://127.0.0.1:8765/`，阅读页为 `/read?article=<article-id>`。已运行的服务若使用旧代码，更新共用模板后需重启一次；之后新增配置自动发现。

交付前在宽屏双栏、窄屏单栏检查逐节切图、末图触底、上行缓冲和图内缩放/拖动；这些检查不代替科学原文核对。

## 公开与素材导出边界

自动发现只登记本地私有文章。现有 `export_github_pages.py` 的 `PUBLIC_IDS` 与 `publication-baseline.json` 继续限定公开篇目，并校验批准版本与文字/图像哈希；新稿 `pending` 不会因为建好或出现在导航中而自动公开。科学修订后重新待审。本地构建与预览均不部署、不授予发布许可。

当前只维护网站这一份正文；管理员从阅读页导出当前版本的标题、富文本正文、配图和封面。长综述可配置整篇或分篇导出，历史公众号副本保留，不再要求每篇另写一份公众号源码。素材导出也不等同于公开发布。

## 标准接口

上述 CLI 是新稿接入的标准接口，无需新增服务器写端点。已有工具也可直接调用同一套 Python API；`validate` 返回错误列表，`plan` 和 `build` 在校验不通过时抛出 `ValueError`：

```python
from pathlib import Path
from validate_article import validate, plan, build

manifest = Path("articles/my-article.json")
errors = validate(manifest, existing=True)
reading_plan = plan(manifest)
result = build(manifest, preview=False)
```

`existing=True` 使用已保存 state 作为正文权威；`build` 只新建缺失 state。共用的纯切图编译器为 `reader_contract.compile_reading_plan(article, blocks)`，不写文件。
